01 — The idea

Code first, model second

  1. Frame 01 · Input

    A thousand a day, all messy

    Abuse reports arrive as HTML, PDFs, CSVs and forwarded chains. At Tata Teleservices there were over a thousand a day, and every one was read by hand.

  2. Frame 02 · Extract

    Deterministic where it matters

    IPs, ASNs, URLs and timestamps come out by regex, before any model sees the text. The fields a security team acts on never depend on a summary being right.

  3. Frame 03 · Model

    AI only where it earns its place

    The model gets clean text and pinned facts, then writes the one thing code can't: the judgement.

  4. Frame 04 · Output

    Honest about what it knows

    Every report lands as a structured incident in one format. I checked the summaries by hand against the analysts' own, looking for missed IPs and invented detail.

Leo

Chrome extension · records and replays browser work

What it is. You record a browser task once — pulling an invoice off a portal, filing a form — and Leo replays it as plain code. No model runs unless the site has changed, so it stays fast and nearly free.

Under the hood. I rebuilt the replay engine, and moved every AI call behind authenticated, rate-limited server routes, so the extension never holds an API key.

  • AI calls, clean run0
  • Ranked selectors / step10
  • E2E scenarios passing17
  • Live-model tests3/3
How it holds up

The hard bit. A recording that replays blindly breaks the day a button moves; an agent that reasons through every step never breaks but never gets cheap. Each step keeps up to ten ranked selectors, so a small redesign usually falls through to the next one. Only when every selector misses does AI step in, find the moved element, repair the step and save the fix back as code.

Where it runs. In your own browser, with your existing logins. There are no passwords to hand over and none are stored.

Next. Self-repair that gets itself unstuck, inputs that change per run, then scheduled cloud runs and store listings.

03Active2026

sudo

Android app · tech news, jobs and a skills radar

What it is. Tech, AI and data news from vetted outlets, with jobs scored against your résumé. The summaries are written on the phone by a model I trained, which picks the article’s own sentences word for word — so it cannot invent a fact the publisher never wrote.

The hard bit. Nothing in the Skills Radar is hardcoded. A term only appears if publication counts show it took off in the last three years, at least five arXiv papers mention it in the last month, and it can be explained by quoting a linked source.

  • SummariesOn‑device
  • Model weights530
  • ROUGE-1 vs lead28.4/27.4
  • Refresh15min
On the summariser

Each sentence gets twenty features — position, TextRank score, title overlap, attribution, numbers — and a 24-unit network scores how likely it belongs in the summary. The app then prints the winning sentences verbatim, in their original order, inside a fifty-word budget. Because it never generates text, it cannot hallucinate.

It was trained on CNN/DailyMail paired with publisher-written highlights, plus articles from the app’s own feeds paired with each publisher’s summary line, filtered for references the article text does not support. On the held-out tech set it scores 28.4 ROUGE-1 against 27.4 for the lead baseline and 24.9 for TextRank, at the same word budget.
